# Vacancy Check

Vacancy Check забирает вакансии Калининградской области с портала «Работа России» (или из локального JSON-файла) и находит в них то, что соискателю непонятно: пропущенные сведения, размытые формулировки и противоречия между полями. Для каждой находки в JSON-отчёте указано, в каком поле проблема, цитата из вакансии и что именно стоит уточнить у работодателя. Проверку делают правила и локальная языковая модель, запускается вручную или по расписанию.

## Возможности

- Загрузка вакансий из локального JSON-файла или через API.
- Проверка условий правилами и языковой моделью.
- Объединение повторяющихся вакансий по ID.
- Ручной запуск и запуск по расписанию.
- Формирование JSON-отчёта.

Проверка охватывает семь тем: название, обязанности, требования, оплата,
график, место работы и тип занятости.

## Как это работает

Точка входа — `main.py`. Порядок обработки:

1. `app/fetch.py` — загрузка вакансий из API постранично или из JSON-файла.
2. `app/normalize.py` — приведение полей к единому формату и удаление дублей по ID. Контакты работодателя не используются в анализе.
3. `app/rules.py` — проверка пропусков, неясностей и отдельных противоречий между полями.
4. `app/llm.py` — поиск моделью неясных формулировок и противоречий в тексте вакансии; проверка предложенных замечаний.
5. `app/report.py` — сохранение отчёта через временный файл с последующей заменой основного. Это защищает предыдущий отчёт при ошибке до успешной замены файла.

## ИИ

По умолчанию используется `gemma4:e2b` через локальный Ollama. Для локального запуска не нужны аккаунт и ключи. При адресе Ollama `http://localhost:11434/v1` запросы к модели остаются на компьютере; первичная загрузка модели и получение вакансий через API требуют интернета. Если настроить внешний `llm.base_url`, текст вакансий отправляется этому сервису.

Модель предлагает замечания о неясных условиях, например «другие задачи по необходимости» или «уточняется на собеседовании», и возможных противоречиях. Код проверяет формат и точность цитат: неподтверждённые замечания отбрасываются. Это не гарантирует правильность смысла — результат нужно проверять.

Если Ollama недоступна, проверка продолжается правилами и в логе появляется предупреждение. При 16 ГБ оперативной памяти и более можно попробовать `gemma4:e4b`, предварительно загрузив её в Ollama и указав в `config.yaml`. Этого объёма может быть недостаточно в зависимости от оборудования и параметров модели.

## Установка

Откройте терминал в папке проекта.
Нужны Python 3.13 и [Ollama](https://ollama.com/download). Зависимости Python закреплены в requirements.txt. Откройте терминал в папке проекта.

### Windows PowerShell

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Если политика PowerShell запрещает активацию, вместо неё можно установить зависимости напрямую:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

В этом случае в следующих командах вместо `python` используйте `.\.venv\Scripts\python.exe`.

### Linux / macOS

```bash
python3.13 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

### Модель

Запустите Ollama и загрузите модель:

```bash
ollama pull gemma4:e2b
```

## Настройки

Основные параметры в `config.yaml`:

| Параметр | Назначение |

| `source.url` | Адрес API источника вакансий |

| `llm.model` | Название модели |

## Результат

По умолчанию отчёт сохраняется в `reports/report.json`. Пример находится в `data/example_report.json`.

В каждом замечании `source: rules` обозначает правило, `source: llm` — модель. У каждой вакансии также есть `llm_checked` и `llm_status`. Статус `model` означает обработку ответа модели в текущем запуске, `cache` — использование кэша, `disabled` — отключённый ИИ, `error` — ошибку обработки модели, `skipped_limit` — пропуск ИИ по лимиту. Проверяйте не только статус, но и сами замечания.

## Проверка

```bash
python -m unittest discover -s tests -v
```

```bash
python -m tools.verify_model --output reports/model-verification.json
```

Автоматические тесты используют имитацию ответов модели. `verify_model` проверяет формальные ожидания на учебных данных без кэша; содержательную корректность результатов нужно проверять отдельно.

## Ограничения

- По предварительной оценке команды проверка ИИ занимает около 3–6 секунд на вакансию; для 200 вакансий это ориентировочно 10–20 минут. Фактическое время зависит от модели, компьютера, загрузки весов, кэша и API и может быть существенно больше.
- Если сервис ИИ недоступен или обработка ответа завершается ошибкой, для вакансии остаются замечания правил; статус может быть `error`.
- Если все замечания модели отклонены проверкой, текущая версия может записать пустой ответ как успешный и закэшировать его. Поэтому `llm_checked` и `model` сами по себе не гарантируют полезного замечания.
- Модель может пропустить проблему или предложить неверное замечание; проверка цитат отсекает часть ошибок, но не доказывает смысловую корректность.
- Некоторые ошибки внутри `results` ответа API могут быть приняты за конец списка страниц. Перед сдачей проверьте и обновите это ограничение, если обработку исправят.
